# 运营看板改版：Board 内树导航 + 统一双列 + 主题出 iframe

Status: accepted（grill 收口 t45u；2026-11-03 壳级筛选与完成合同额看板共识补丁）

## Context

澄清（t65u / grill-with-docs）后拍板：取消「所有东西放一页」的限制后，不另起顶栏导航体系，而在 Board 内容区左侧用看板目录切换节点；所有节点右侧统一双列栅格；主题放在 Next 壳全局 header（iframe 外），避免每个看板 HTML 各自一套主题控件。

2026-11-03 共识补丁：筛选从运营看板 iframe「内容顶栏」**上提为 Board 壳级筛选条**（header 下、目录与内容上，整树共用；锁 2026、去业务类型）；「完成合同额看板」由占位升级为与「运营看板」同形态的专用静态 HTML + iframe，内容信息架构对齐项目追踪表报告线概览（第一版 demo）。

## Considered Options

- **A. catalog 多入口 / 多顶栏路由**：每个看板独立全屏页。否决——用户要「一棵树整合很多看板」，且组织图 Board 仍进同一 `/board`。
- **B. 仅运营看板双列，其他节点原样嵌入**。否决——用户明确所有树节点统一双列栅格。
- **C. 主题仍留在各 iframe 内容顶栏**。否决——无法对整棵树全局生效，且与「内容顶栏只留下拉」冲突。
- **D. 完成合同额用 Board 内 React 面板而非 iframe**。否决（2026-11-03）——用户要求与「运营看板」同形态（专用静态 HTML + iframe）。
- **E. 筛选仍留在运营看板 iframe 内容顶栏、仅该节点可见**。否决（2026-11-03）——用户要求筛选上提为壳级、用于所有看板；并去掉业务类型、年度固定 2026。

## Consequences

- 实现上 Board 页成为壳内导航中枢；占位节点不新开路由。
- 壳级筛选条始终可见；`index.html` 去掉原三下拉，改为收壳注入的 year/unit；business 不再参与筛选。
- 「完成合同额看板」去 placeholder，右侧切至专用 HTML iframe；信息架构跟源概览，第一版 demo；不跨仓直连报告线 API。
- 其他仍为占位的节点继续共用占位壳；组织图一级入口与 `/org-chart` 行为保持不变。
