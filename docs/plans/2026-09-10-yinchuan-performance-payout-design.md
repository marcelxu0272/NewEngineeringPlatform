## 0. 相对 0.1 的勘误

| 0.1 错误说法 | 正确口径 |
| --- | --- |
| K1/K2/K3 就是质量/进度/响应度 | 两套东西。K1/K2/K3 是奖金提取与审核系数；质量/进度/响应度只出现在第三步评估 |
| K1 是质量包、允许 100% 派完 | K1 是项目经理从**可分配金额**里提取奖金的比例（可分配金额见决策 15） |
| 专业间按金额拆到专业 | 专业间按**比例**拆，所选专业比例合计必须 100% |
| 张鑫/安小华「审核通过」K2/K3 包 | 审核阶段由配置的 K2、K3 审核人分别给出系数，默认都是 1 |
| 专业内由项目经理审 | 专业内由该专业的**专业室主任**审 |
| 评估系数 0~2 | 三项评分范围 **0.7 ~ 1**，默认 1 |

### 已确认决策（2026-09-11）

1. **刚发起不预生成个人行。** 专业间只能定到各专业，此时不能确定到人；个人行只在专业内审批通过后才出现。
2. **可以驳回。** K2、K3 审核人在专业间待审时均可驳回整单；专业室主任在专业内待审时可以驳回该专业单。
3. **审核人和系数限制可配置。** 张鑫、安小华以及 0.7~1 等数字只是演示默认值，不是写死在流程里的人/区间。
4. **专业内单由系统自动建草稿。** 专业间通过时，为每个**比例 > 0 的单元行**各生成一张 `INTRA_DRAFT`，专业负责人不手动新建。同专业多单元则多张单。
5. **通过即不可改（终止除外）。** `INTER_APPROVED` 后不能改 K1 和专业比例，`INTRA_APPROVED` 后不能改专业内比例，`EVAL_DONE` 后不能改评分。本期不做作废重开、不做版本号；**允许「终止」整条派发链**（见决策 19）。
6. **评分折减不做二次分配。** 综合评分小于 1 时少发的部分不回收、不二次分配，公式算多少就是多少。
7. **同一项目可多次派发。** 不体现「轮次」概念，随时可以再发起一张专业间单；同一项目同时最多一份进行中的专业间单（草稿 / 待审 / 已驳回都算进行中；**已终止不算进行中**），已评估完成或已终止的历史单保留可查。
8. **允许自审。** K2/K3 审核人恰好是本项目项目经理时可以自审；K2 与 K3 也可以是同一人（仍分两次确认）。
9. **绩效查询按身份隔离；主页签按角色裁剪。** 一级页签为「项目绩效查询」「个人绩效查询」（不再套在同一「绩效查询」下的子页签）。切身份会换可见范围，不只是换按钮。工程师默认落在「个人绩效查询」。主页签可见规则见 **0.30**。
10. **评估是选选项，不是手填系数。** 质量 / 进度 / 响应度各给若干描述性选项，选中后系统带出对应系数再加权。权重固定为 **质量 40%、进度 30%、响应度 30%**（业务原表第四项已取消，表头上的 30/20/20 作废，以本口径为准）。
11. **发起前置。** 只有项目经理能选到**自己担任项目经理**的项目；且该项目必须已做**任务书**，否则不可发起。
12. **专业间按任务书单元全列。** 任务书每个单元（工作包）出一行：单元号、单元名称、专业、专业负责人、专业间比例。不可增删行；无需分配的填 0；全表比例合计 **必须等于 100%**。比例为 0 的单元**出账/下游**不出账、不建专业内单；**编辑态仍全列展示**，见 7.1。
13. **专业负责人只读引用任务书。** 每一行的专业负责人 = 该单元在任务书上的负责人，提交时快照，界面不可改、不提供下拉。同专业多单元可出现多行（负责人可相同也可不同）。
14. **专业内工程师取自本单元本专业派工全量历史。** 名单 = 当前专业内单对应的**项目 + 单元 + 专业**下，全量历史派发过工时的工程师（按人去重），**排除已离职**；不限定时间段、不因跨年截断。不以专业负责人为过滤条件，也不是专业花名册全员。本单元本专业未派过工时（或派过的人已全部离职）则名单为空，不能提交专业内。
15. **计算基数改为可分配金额。** 项目主数据仍保留不含税合同额。发起时界面展示并快照的基数 `C` = **可分配金额** = `max(0, 不含税合同额 − 该项目已完成评估且未终止单据的已分配实发合计)`。tooltip 文案：「不含税合同额 - 已分配金额」。可分配金额为 0 不可发起。公式里凡写 `C` / 「可分配金额」均指该快照，不是每次现算的合同额。**已终止单据的实发从已分配中释放**，可重新派发。
16. **K2/K3 未确认不展示系数与预估包。** 列表、详情、公式条中：K2/K3 未确认显示 `—`（不拿默认值冒充已填）；**预估分配金额 / 专业分配金额**在 K2、K3 都确认前也为 `—`。默认值仅用于驳回清回与确认前的内部校验，不面向列表预估展示。
17. **办事页在当前 tab 内切换，不整页顶掉一级 tab。** 与「项目经理评估」一致：一级 tab 栏始终可见；各 tab 用本页视图状态切换列表 / 填写 / 审核 / 详情（见 7.0a）。仅驳回、终止二次确认为小弹窗。
18. **操作文案统一为「填写 / 审核 / 查看」。** 专业间项目经理草稿/驳回 →「填写」；K2/K3 →「审核」；专业内负责人 →「填写」；只读详情一律「查看」。不再用「编辑」「分配比例」「填 K2/K3」。另有「终止」（见决策 19）。
19. **专业间可终止整链。** 本项目项目经理可终止（**系统配置身份可代操作**）。任意未终止状态均可点；二次确认后：该专业间单及关联全部专业内单、评估单状态变为「已终止」，未完成流程结束。已终止不再出终止按钮。已产生分配实发的终止单在绩效查询列表仍可查，**顶部 KPI 不计**；实发从可分配基数释放。
20. **单据编号父子规则。** 专业间 `YCJX-`+四位流水（如 `YCJX-0001`）；专业内 `{专业间号}-`+三位流水（如 `YCJX-0001-001`）；评估 `{专业间号}-PG`（如 `YCJX-0001-PG`）。见 **0.35**。

## 1. 一句话

银川绩效是总分结构：先定项目可分配绩效和专业切分，再切到人，最后乘上项目经理的综合评分。

**工程师在一个项目上的奖金：**

```
可分配金额 × K1 × K2 × K3 × 专业间比例 × 专业内比例 × 综合评分系数
```

---

## 2. 三级流程

```text
开始
  → ① 专业间：项目经理选本人已做任务书的项目，填 K1；
           任务书每个单元全列（单元号、单元名称、专业、负责人只读），填比例（可 0；合计必须 100%），提交
  →     K2 审核人给 K2、K3 审核人给 K3（人选和默认值来自配置）
           任一人驳回 → 整单退回项目经理（K2/K3 清回配置默认值）
           两人都确认 → 专业间完成（此时仍无个人行）
  → ② 专业内：比例 > 0 的单元行自动建单；
           专业负责人给「本人在本项目派过工时」的工程师填分配比例（合计 100%）
  →     该专业的专业室主任审批
           驳回 → 退回该专业负责人
           通过 → 才生成该单元下的个人行
  → ③ 项目经理评估：先看本人项目列表，点进某一项目后再评该项目内的人；
           质量 / 进度 / 响应度各选一项（选项文案只是选分说明，选后与锁定后主显示分数）；
           专业内未完成的单元展示当前状态，该单元暂不评人
  →     综合评分系数 = 所选质量系数×权重Q + 所选进度系数×权重P + 所选响应度系数×权重R
  → 个人奖金按公式锁定
结束
```

## 3. 系数与计算

### 3.1 项目奖金包（第一步）

| 符号 | 谁给 | 含义 | 取值 |
| --- | --- | --- | --- |
| 不含税合同额 `C` | 项目主数据，只读 | 计算基数 | 金额，千分位 |
| 绩效系数 K1 | 项目经理 | 从合同额里拿多少比例当奖金 | 界面用百分比，存小数。上下限见配置 |
| 绩效系数 K2 | 配置的 K2 审核人，审核时填写 | 审核系数 | 默认值、上下限见配置 |
| 绩效系数 K3 | 配置的 K3 审核人，审核时填写 | 审核系数 | 默认值、上下限见配置 |

```
项目奖金包 = C × K1 × K2 × K3
```

界面将「项目奖金包」展示为**绩效金额**。

K2/K3 未确认时，明细里按**配置默认值**预估，并标明「未锁定」。两人都确认后，绩效金额锁定。

K1、K2、K3 的允许区间彼此独立，都从配置读，不互相套用。评估三项的可选值只由选项列表决定，与 K1/K2/K3 无关。

演示默认：K2 审核人张鑫、K3 审核人安小华；K2/K3 默认 1.00。

### 3.2 专业分配金额（第一步切分）

#### 发起前置

- 项目下拉**只出现当前身份作为项目经理、且已存在任务书**的项目。别人的项目、无任务书的项目都不出现。
- 选中项目后，系统从该项目任务书带出：可分配金额（只读）、**全部单元行**（不可增删行）。

#### 单元行怎么填

| 列 | 规则 |
| --- | --- |
| 单元号 | 任务书工作包 id，只读 |
| 单元名称 | 任务书工作包 name，只读 |
| 专业 | 该单元所属专业，只读 |
| 专业负责人 | 该单元任务书负责人，只读引用，不可改 |
| 专业间比例 | 百分比，允许 0；存万分比整数 |

**合计校验：** 各单元比例之和必须 **等于 100%**（整数相加：等于 10000）。小于或大于 100% 都不能提交。允许个别单元填 0，只要全表合计为 100%。

```
单元分配金额 = 项目奖金包 × 该单元专业间比例
```

例：WP1 设计-设计-管道 25%、WP4 设计-设计-管道 15%、WP2 设计-设计-工艺 60%、WP3 设计-设计-电气 0%，合计 100%。出账与下游只出前三个比例 > 0 的单元；电气无专业内单。

同专业可多行（不同单元）；负责人随单元带出，无需选择。

### 3.3 专业内比例（第二步）

仅对专业间比例 > 0 的**单元行**建单。专业负责人给名单内工程师填比例，**合计必须等于 100%**。未列入或比例为 0 的人本单元本单没有个人行。

**名单来源：** 当前单元、当前专业下，本项目**全量历史**派发过工时的工程师（按人去重），**排除已离职人员**。不限定时间段，不因项目跨年度而截断。不以专业负责人为过滤条件；不是专业花名册，也不是任务书全员。名单为空（本单元本专业从未派工，或派过的人已全部离职）时不能提交，提示「本单元本专业暂无派工的在职工程师」。

**编辑列：** 姓名、专业内比例、预估分配金额。预估分配金额 = 本单元分配金额 × 专业内比例，随比例实时试算；比例为 0 显示 `—`。无「说明」列。

```
评估前个人应发 = 单元分配金额 × 专业内比例
               = C × K1 × K2 × K3 × 专业间比例 × 专业内比例
```

审批人：该专业的**专业室主任**（主数据，不是项目经理，也不是任务书里的专业负责人）。

### 3.4 综合评分系数（第三步，与 K1/K2/K3 无关）

项目经理**不手填系数**，而是对每人的三项各选一个分数；选项文案只是选分时的说明，选后与锁定后主显示分数。系统用该选项绑定的系数参与加权。选项文案、系数、默认选项、权重都来自配置；演示缺省如下。

#### 完成质量（权重 0.40）

| 系数 | 选项说明（选分时展示） |
| --- | --- |
| 1.00 | 按项目质量要求完成 |
| 0.90 | 项目内审无不合格项，但整改问题较多 |
| 0.80 | 项目内审有不合格项 |
| 0.70 | 业主有书面质量问题反馈 |

#### 进度（权重 0.30）

| 系数 | 选项说明（选分时展示） |
| --- | --- |
| 1.00 | 按项目计划完成 |
| 0.90 | 本专业按计划，但影响其他专业进度 |
| 0.80 | 影响本专业及其他专业进度 |

#### 响应度（权重 0.30）

| 系数 | 选项说明（选分时展示） |
| --- | --- |
| 1.00 | 业主及项目团队无负面反馈 |
| 0.90 | 公司内部有书面的负面反馈 |
| 0.80 | 业主有书面的负面反馈 |

三项默认选项均为系数为 1.00 的那一条。进度、响应度没有 0.70 档，界面上也就不出现。

```
综合评分系数 = 质量系数×权重Q + 进度系数×权重P + 响应度系数×权重R
个人奖金     = C × K1 × K2 × K3 × 专业间比例 × 专业内比例 × 综合评分系数
```

三项都选默认项、且三权重合计为 1 时，综合评分系数 = 1，个人奖金 = 预估分配金额。评估提交后个人奖金锁定。评分折减少发的部分不做二次分配。

评估页选中后与锁定后主显示分数；文案只出现在下拉选项里帮助选分。查看详情与绩效查询同时写清「分数（选项说明）」。

### 3.5 规则配置

单独一页维护，不写进流程代码。演示默认值等于当前业务口径，改配置立刻影响**新填报**的校验和角色切换上的审核人姓名。

#### 可配项

| 配置项 | 演示默认 | 校验 |
| --- | --- | --- |
| K2 审核人 | 张鑫 | 必选，从人员名单选；允许与本项目项目经理为同一人（自审） |
| K3 审核人 | 安小华 | 必选，从人员名单选；允许与 K2 为同一人（仍分两次确认）；也允许是项目经理 |
| K1 最小 / 最大 | 0.01% / 50% | 最小 ≥ 0，最大 ≥ 最小；K1 用百分比 |
| K2 最小 / 最大 / 默认 | 0.00 / 2.00 / 1.00 | 最小 ≤ 默认 ≤ 最大 |
| K3 最小 / 最大 / 默认 | 0.00 / 2.00 / 1.00 | 同上 |
| 质量 权重 / 默认选项 / 选项列表 | 0.40 / 系数 1.00 那条 / 见 3.4 | 权重 ≥ 0；选项 ≥ 1 条；每条有文案和系数；默认选项必须在列表内 |
| 进度 权重 / 默认选项 / 选项列表 | 0.30 / 系数 1.00 那条 / 见 3.4 | 同上 |
| 响应度 权重 / 默认选项 / 选项列表 | 0.30 / 系数 1.00 那条 / 见 3.4 | 同上 |

保存配置时：三项权重合计必须等于 1.00，否则不能保存。专业间比例合计 **必须等于 100%**、专业内比例合计必须 100% 是流程硬规则，不做配置。评估不再配「最小 / 最大」连续区间——可选值完全由选项列表决定。

#### 配置何时生效

- **审核人：** 项目经理提交专业间时，把当时的 K2/K3 审核人 **写进该单快照**。之后改配置，进行中的单仍由快照上的人审、驳回；新提交的单用新审核人。
- **系数上下限和默认值：** 填报、确认时按**当前配置**校验。已确认、已锁定的数字不因改配置而作废或重算。
- 明细账公式里的「谁填的 K2/K3」显示快照姓名，不显示后来改掉的配置。
- 角色切换列表里的「K2 审核人 / K3 审核人」跟当前配置走，方便演示换人；打开一张历史单时，按钮是否可点看该单快照，不看当前配置。
- **K2/K3 默认值也要快照。** `PayoutConfig` 全局一份、不留历史版本，所以单据除了快照审核人，还要快照提交（或重提）当时的 K2/K3 默认值（`k2Default`、`k3Default`）。驳回后清回的是这两个快照值。**重提时与审核人一并按当前配置刷新**，见 6.1。
- **评估选项与权重在提交时落库。** 评估提交前，改权重或改选项文案会影响预估值（预估本来就标「未评估」）。评估一提交，所选选项 id/文案/系数、三项权重和综合系数一并落库，之后不随配置变。

#### 谁能改

演示增加身份「系统配置」，只有该身份能改规则配置。其他人进配置页只读。

### 3.6 取整、精度与尾差

公式是六层连乘。取整口径不定死，明细账上父行和子行必然对不上。

**比例存整数万分比，不用浮点。** 专业间比例、专业内比例一律存 0 ~ 10000 的整数（40% 存 4000），界面按百分比显示两位小数。专业间合计判定为整数相加 **等于 10000**；专业内合计判定为整数相加 **等于 10000**。不设浮点容差。禁止 `0.4 + 0.6 === 1` 这类浮点比较。

**系数同样按定点存。** K1 界面输百分比、存万分比整数；K2、K3、质量、进度、响应度存两位小数。综合评分系数由三项加权得出，保留三位小数参与计算；**展示时始终三位小数**（如 `1.000`、`0.940`、`0.870`），不因末位为 0 而省略成 `1` 或 `1.00`。

**金额中间不取整，只在展示取整。** 项目包、专业包、个人应发全程按全精度算，展示时统一四舍五入到分。

**尾差挂本级最后一行。** 明细账分组表必须满足「子行展示值之和 = 父行展示值」。因此专业行按顺序四舍五入后，把差额（通常 ±0.01）补到最后一个专业行；个人行同理补到本专业最后一位工程师。查看详情里该行注明「含分配尾差 +0.01」。

注意：个人行合计等于专业包，只在该专业全部工程师综合评分系数都为 1 时成立。评分小于 1 时，个人行合计**小于**专业分配金额，这不是尾差，见 4.3 的双金额展示。

## 4. 总分怎么记账、怎么展示

流程是从上往下长的：发起时还没有人。但业务上又希望「每个项目、每个专业、每个人」都能看到一条独立记录和直白公式。处理方式如下。

### 4.1 一条明细账，三种粒度，按流程长出子行

所有计算都进同一本「奖金明细账」。每条记录有粒度：`项目` / `专业` / `个人`。

| 何时 | 生成什么 | 还不生成什么 |
| --- | --- | --- |
| 项目经理提交专业间 | 1 条项目行 + N 条专业行（N = 比例 > 0 的专业） | 个人行；比例为 0 的专业 |
| 专业负责人提交专业内，室主任通过 | 该专业下 M 条个人行（M = 填了比例且 > 0 的工程师） | — |
| 项目经理提交评估 | 不新增行，回写个人行的三项评分、综合系数、锁定奖金 | — |

**已确认：不在第一步按花名册预生成个人行。** 刚发起只能到各专业，不能确定到人。专业内名单来自派工记录，没分到比例的人不上账。

专业行在尚未拆到人时，状态为「待拆分到人」，展开区说明：「本专业分配金额已定，待专业负责人分配到工程师。」

### 4.2 每条记录都把公式写全

同一套乘法，缺的因子标成「本级不适用」或「待填写」，预估金额和锁定金额分开。

**项目行（第一步提交后就有）：** 横向公式，上排数字、下排系数名称。K2 / K3 在名称下用徽章标状态（已确认 / 待审核）；预估分配金额在两边都确认前显示 `—`，确认后标已锁定。不写审核人、不写「项目主数据只读」等说明。

专业间「查看」进入的派发详情，顶部状态条**只展示专业间状态**（草稿 / 待审核 / 已通过 / 已驳回），与专业间列表一致；说明文案只写本阶段待办（如待 K2/K3、待项目经理重提、K2/K3 均已确认）。**禁止**在此串出评估态「专业内未完成」或各专业内进度句。专业内进度只出现在专业内详情、评估详情。

```
7,500,000.00  ×  1.80%  ×  1.00  ×  1.00  ＝  135,000.00
不含税合同额   绩效系数 K1  绩效系数 K2  绩效系数 K3   绩效金额
                         待审核        待审核           预估
```

项目行下方列出**各单元的专业间比例**（含比例为 0 的行）：表（单元号、单元名称、专业、负责人、比例、专业分配金额；0% 行为 `—`）+ ECharts 环形饼图。饼图不带图例（表即名单）。扇区 label 为**单元名称**（或「专业·单元」）+ 专业间比例（两位小数百分比），用短指引线贴在环外，完整显示不截断。鼠标悬停 tooltip 显示单元名称、专业间比例、专业分配金额。仅比例 > 0 的单元入图。**历史派发记录**在专业间比例区块下方（同一项目、不含草稿、不含本单）：NO、状态、编号、金额，表底合计金额。**不要**在项目行写专业内比例、综合评分系数、已分配实发。

**单元行（专业内「查看详情」）：** 只展示本单元分配金额、人员分配名单（姓名、专业内比例、分配金额 = 单元包 × 专业内比例）、以及**仅本单元专业内单**的操作日志。不展开 C × K1 × K2 × K3，不带专业间日志、不带评估日志。名单按姓名拼音升序；尚未分到人时名单空。

操作日志不用表格：左侧日期（`YYYY/MM/DD`）和时间，右侧一句流转说明（如「王磊已提交专业间派发，正在等待绩效系数 K2 审核人（张鑫）、绩效系数 K3 审核人（安小华）；」），按时间正序。

室主任待审时列表只出「审批」，不出「查看详情」（审批弹窗已含金额和名单）。

**个人行（第二步通过后才有）：** 同一套横向公式，因子为：不含税合同额 × K1 × K2 × K3 × 专业间比例 × 专业内比例 × 综合评分系数 ＝ 个人奖金。K2 / K3 仍只出已确认 / 待审核；个人奖金标预估或已锁定。不写填写人、不展开三项评分文案。

未评估时综合评分系数按三项默认选项预估，展示为 `1.000`。

界面要同时能看：当前算到哪一步、K2/K3 是否已确认、预估还是最终奖金。禁止只给一个总额不给因子。

### 4.3 绩效查询怎么排

一级页签为「项目绩效查询」「个人绩效查询」，各自扁平列表，不再用分组树。

**项目绩效查询（一行一张专业间单）：**

列：编号、项目号、项目名称、绩效系数 K1、已分配实发、状态、更新时间、查看。

状态含待审核 / 已驳回 / 专业内未完成 / 待评估 / 已完成 / **已终止**。草稿不出现。工程师身份项目页空态（5.1）。

顶部年度 KPI（tip 须说明：**已终止单据不计入本统计；列表仍可查有实发的终止记录**）。点 KPI 进同 tab 统计页；统计明细同样排除已终止。

**个人绩效查询（一行一位工程师）：**

列：编号、项目、专业、姓名、完成质量 / 进度 / 响应度、实际分配金额、查看。

仅专业内已通过、已生成个人行的工程师出现（含已终止链上曾锁定/预估的人行，便于对账）。KPI 同样排除已终止。

- 点「查看」按 4.2 展示横向公式。
- 各自筛选、分页；点搜索后执行；每页 10 条。

### 4.4 和三个操作页的关系

| 页 | 职责 | 写绩效数据 |
| --- | --- | --- |
| 专业间 | 填 K1、选专业、填比例；K2/K3 审核人按该单快照填系数；**可终止整链** | 提交时写项目记录+专业切分；终止时整链置已终止并释放已分配 |
| 专业内 | 专业负责人填人与比例；室主任审批 | 审批通过后写个人行 |
| 项目经理评估 | 对已有个人行选三项评估选项 | 提交后回写选项、系数、锁定个人奖金 |
| 项目 / 个人绩效查询 | 只读对账；KPI 不计已终止 | 不写 |
| 规则配置 | 配 K2/K3 审核人、系数限制、评估选项与权重 | 不写绩效数据 |

三个操作页是办事的；绩效查询是对账的。两边看到的数字必须同一套公式。

### 5.0 快照管权限，配置管展示

全局原则，各页只引用不另起口径：

- **操作权限看快照：** 确认系数、驳回、审批、评估等按钮是否可点，永远依据**该单据提交时写入的快照**（审核人、负责人等）。管理员中途改配置，不影响正在操作的这张单。
- **展示与待办入口看配置：** 顶部角色切换后的**各一级页签右侧待办数字**、规则配置页上的审核人姓名，跟随**当前配置**。数字按页签拆开：专业间（草稿/已驳回/待确认 K2 或 K3）、专业内（草稿/已驳回/待室主任审）、项目经理评估（待评估）。数量为 0 不显示；顶部不再汇总「待办 N 项」。绩效查询、规则配置无待办数字。

两者解耦，互不影响。

### 5.1 绩效查询可见范围

| 身份 | 项目页签 | 个人页签 |
| --- | --- | --- |
| 项目经理 | 自己担任项目经理的派发单 | 这些单下全部个人行 |
| K2 / K3 审核人 | 自己出现在该单快照上的派发单 | 这些单下全部个人行 |
| 专业负责人 | 自己负责专业所属的项目行（金额可见，便于对照专业包） | 仅本专业个人行 |
| 专业室主任 | 同专业负责人，范围限自己所辖专业 | 仅本专业个人行 |
| 工程师 | 不展示（空态） | 仅自己的个人行；可看到所属项目名、专业名，不展示他人、不展示项目奖金包 |
| 系统配置 | 全部 | 全部 |

列表空态：当前身份过滤后无行时，用「当前身份暂无可见数据」，不要误显示成系统无数据。待办入口与操作按钮的判定规则见 5.0。

## 6. 状态

### 6.1 专业间（同一项目同时最多一份进行中；可多次发起）

| 状态 | 含义 | 谁可操作 |
| --- | --- | --- |
| `INTER_DRAFT` | 草稿 / 驳回待改 | 项目经理改 K1 和专业比例、提交 |
| `INTER_PENDING` | 待 K2、K3 | 该单快照上的 K2/K3 审核人填确认系数；任一人可驳回整单 |
| `INTER_APPROVED` | K2、K3 都已确认 | 可发起专业内 |
| `INTER_REJECTED` | 已驳回 | 同草稿 |
| `INTER_TERMINATED` | 已终止 | 只读查看；整链结束 |

K2、K3 各自 `pending / confirmed`。两个都是 `confirmed` 才到 `INTER_APPROVED`。

**终止（决策 19）：** 本项目项目经理或系统配置身份，对任意**未终止**专业间单可点「终止」（红色、二次确认）。确认后：本单 → `INTER_TERMINATED`；关联全部专业内 → `INTRA_TERMINATED`；评估单（若有）→ `EVAL_TERMINATED`。未完成流程不可再办。已产生实发从可分配基数释放；绩效查询列表可查，KPI 不计。已终止不算进行中，同项目可再发起。

**多轮派发：** 不体现轮次编号。同一项目在上一份派发整链走完（评估 `EVAL_DONE`）或**已终止**之后，项目经理可再新建一张专业间单；历史单与明细账保留。同一项目若已有状态为 `INTER_DRAFT` / `INTER_PENDING` / `INTER_REJECTED` 的专业间单，或已有专业间已通过但评估尚未 `EVAL_DONE` 的派发，则不能再新建——提示「该项目已有进行中的派发」。允许 K2/K3 审核人与本项目项目经理为同一人（自审）。

**专业间驳回（已确认可以驳回）：**

- 仅 `INTER_PENDING` 时，该单快照上的 K2 或 K3 审核人**任一人**可驳回整单，原因必填。
- 对方若已确认自己的系数，驳回后一并作废：K2、K3 都清回**该单快照上的** `k2Default` / `k3Default`，状态都回到 `pending`。
- 单据回到 `INTER_REJECTED`（等同草稿），由项目经理改 K1 和专业比例后重提。
- **重提时同步刷新审核上下文：** 按重提时刻的当前配置，重新写入 `k2ReviewerId` / `k3ReviewerId` **以及** `k2Default` / `k3Default`。此后若再次被驳回，清回的是这次重提写入的新默认值，不是首次提交时的旧默认值。重提 = 用当前配置重新初始化这张单的审核上下文。
- 专业间尚未通过，专业内还不能发起，因此驳回时没有个人行，也不存在下游作废问题。
- 一旦进入 `INTER_APPROVED`，K2 / K3 审核人不能再驳回。

### 6.1a 专业间驳回后明细账

项目行、专业行保留（同一张单改完重提，不另开新单），金额改回按该单快照的 K2、K3 默认值预估，并标明「已驳回，待项目经理修改」。仍无个人行。

### 6.2 专业内（每个比例 > 0 的单元一行一张单）

| 状态 | 含义 | 谁可操作 |
| --- | --- | --- |
| `INTRA_DRAFT` | 草稿 / 驳回待改 | 该专业负责人编辑、提交 |
| `INTRA_PENDING` | 待室主任审 | 该专业室主任通过或驳回 |
| `INTRA_APPROVED` | 已通过 | 生成个人行，可评估 |
| `INTRA_REJECTED` | 已驳回 | 同草稿 |
| `INTRA_TERMINATED` | 已终止 | 只读；随专业间终止写入 |

前置：专业间必须是 `INTER_APPROVED`。比例合计必须 100%。

单据由系统在专业间通过的那一刻自动创建：每个**比例 > 0** 的单元行各一张 `INTRA_DRAFT`，带出单元号/名称、单元分配金额、该行快照的专业负责人、以及该**项目 + 单元 + 专业**下全量历史派工且在职的工程师名单（建单时快照到 `candidateUserIds`）。专业负责人只填比例，不新建单、不改名单范围。

**专业内驳回：** 仅 `INTRA_PENDING` 时，该专业室主任可驳回，原因必填。退回 `INTRA_REJECTED`（等同草稿），由该专业负责人改比例后重提。个人行在通过之前尚未生成，驳回不会删人。一旦 `INTRA_APPROVED`，室主任不能再驳回。

### 6.3 评估

| 状态 | 含义 |
| --- | --- |
| `EVAL_BLOCKED` | 还有专业内未通过，不能评估 |
| `EVAL_PENDING` | 本项目所有专业内都已通过，待项目经理评 |
| `EVAL_DONE` | 已提交，个人奖金锁定 |
| `EVAL_TERMINATED` | 已终止；随专业间终止写入（无评估单时仅专业间/专业内终止即可） |

评估对象 = 明细账里该项目已有的全部个人行。未拆到人的单元会挡住整项目评估。评估详情按**单元**分组（同专业多单元分多组）。

`EVAL_DONE` 后不提供撤回或重评。评错分可终止整链后重新发起（基数已释放），或重置演示数据。

### 6.4 通过之后不能改（终止除外）

三级各自通过后都不再提供业务侧修改入口：`INTER_APPROVED` 后项目经理不能改 K1 和专业比例；`INTRA_APPROVED` 后专业负责人不能改人和比例（工程师离职等场景本期不处理）；`EVAL_DONE` 后评分和个人奖金锁定。本期不做作废重开、不做版本号。**例外：专业间「终止」可结束整链并释放已分配实发（决策 19）。**

### 6.5 操作日志

每张单挂一条流水，明细账的查看详情要靠它回答「这个因子是谁在什么时候填的」。

| 字段 | 说明 |
| --- | --- |
| `action` | `SUBMIT` / `CONFIRM_K2` / `CONFIRM_K3` / `REJECT` / `APPROVE` / `EVALUATE` / `TERMINATE` |
| `operatorId` `operatorName` | 操作人，姓名一并落库，改配置或改花名册不影响历史显示 |
| `value` | 本次填入的值，如 K2 = 1.00；驳回 / 终止时为空 |
| `comment` | 驳回原因（必填）；终止原因（选填） |
| `at` | 时间，`YYYY-MM-DD HH:mm` |

`InterSheet` 原先没有驳回原因和确认人字段，一并补齐，见第 8 节。

### 7.5 规则配置

仅「系统配置」身份可编辑，其他人只读。

表单分区：

1. **审核人**：K2 审核人、K3 审核人员工选择（允许与项目经理同一人）。

## 10. 本期范围

做：独立模块；专业间（本人项目 + 任务书前置、K1 + 按单元全列比例 + 负责人只读引用 + K2/K3）；专业内（按单元建单、派工工程师比例 + 室主任审）；评估（选项选择 + 权重可配）；绩效查询（项目 / 个人两个列表，按身份隔离）；规则配置（审核人 + 系数限制 + 评估选项）；同一项目可多次发起派发。

不做：原绩效系统；成本/财务/薪酬；中心外人员能不能派；看板；导入导出；消息；真权限；任务书/派工维护页（只读 mock）。本期仍不写原型。

以下几条容易被当成遗漏，明确不做或不这样：

- **剩余奖金池。** 综合评分小于 1 时，未发出部分不回收、不二次分配。专业间合计必须 100%，不存在「未切到单元」的剩余。
- **轮次概念。** 可多次派发，但不展示「第 N 轮」，也不存 `period` 字段。
- **通过后修改。** 不做作废重开、不做版本号、不做评估撤回；**允许终止整链**（决策 19）。
- **手动增删专业间行 / 改负责人。** 行完全由任务书单元带出；负责人只读，不可下拉改派。同专业多单元自然多行、多张专业内单（这是要做的，不是不做）。
- **花名册分配。** 专业内不用专业花名册全员，只用该负责人在本项目的全量历史派工工程师（剔离职）。
- **配置历史版本。** `PayoutConfig` 只有当前一份，历史值靠单据快照。
- **自审回避。** 不做；项目经理可以同时是 K2/K3。
- **明细账操作人冗余字段。** 追溯走单据 `logs[]`，本期不为 `LedgerEntry` 预留 `lastOperator*`。

## 11. 验收

1. 专业间比例合计不是 100% 不能提交（0%、90%、101% 均不可）；个别专业可以为 0，只要全表合计为 100%。K1 超出当前配置区间不能提交；演示默认上限 50%。
2. K2/K3 审核人来自配置（演示默认张鑫、安小华）。提交专业间时写入单据快照；只有快照上的人能填对应系数或驳回整单。改配置不影响进行中单据的审核人。驳回后 K2/K3 清回该单快照默认值，退回项目经理。允许自审。操作按钮看快照、待办展示看配置（见 5.0）。
3. 专业间未完成，不能做专业内。
4. 专业内比例合计不是 100% 不能提交；通过后才出现个人行。
5. 室主任审专业内，项目经理不审专业内。
6. 评估三项与 K1/K2/K3 无关；界面是下拉选分数，不是手填系数；展开时文案仅作选分说明，收起后与锁定后主显示分数；权重合计必须为 1 才能保存配置。
7. 马超个人奖金（演示主路径、系数全 1）= `10,000,000 × 0.02 × 1.00 × 1.00 × 0.40 × 0.50 × 1.000 = 40,000.00`。查看详情中七个因子（C、K1、K2、K3、专业间比例、专业内比例、综合评分系数）均可见；每个因子注明含义、填写人；评估三项额外显示所选选项文案。综合评分系数展示为三位小数（如 `1.000`）。
8. 刚发起且已提交后，绩效查询「项目」页能看到该单，「个人」页还没有该项目的人；比例为 0 的专业不生成下游单。编辑态专业表仍能看到 0% 行并改回 > 0。
9. 列表 10 条/页（按项目行），点搜索才过滤；弹窗固定并锁滚动。
10. 规则配置可改审核人、系数上下限/默认、评估选项与权重；权重合计不是 1 不能保存配置。演示环境可一键恢复演示默认值。
11. 比例校验走整数万分比；不出现浮点误差导致的误判。
12. 以管道专业为例：专业分配金额 `80,000.00`，马超 `40,000.00` + 刘洋 `40,000.00` = `80,000.00`，子行之和精确等于父行。若因四舍五入产生 ±0.01 尾差，尾差补到本专业最后一位工程师行（按展示顺序），并在该行查看详情中标注「含分配尾差 +0.01」或「-0.01」。
13. 专业间驳回后，K2、K3 都回到**该单当前快照**的默认值且状态为 `pending`；重提后快照（含审核人与默认值）按重提时刻配置刷新；此后再驳回清回的是新快照。预置第 4 份单据可直接验驳回态。
14. 评估提交后再改权重或选项配置，已锁定的个人奖金不变。
15. 绩效查询每行的查看详情能点出「谁在什么时候填的」，取自单据操作日志。
16. 专业间通过后，仅为比例 > 0 的**单元行**各自动出现一张专业内草稿单（同专业多单元则多张）。
17. 同一项目评估完成后可再发起新的专业间单；已有进行中派发时不能再建，并有明确提示。
18. 切换到工程师身份，绩效查询默认在「个人」页且只见自己的行，项目页为空；切换到专业负责人，个人页只见本专业；系统配置身份两个页签均可见全部。
19. 项目经理下拉看不到他人项目、看不到无任务书项目。
20. 专业间编辑表按任务书单元全列；负责人只读带出，不可改；演示 p018 双管道同负责人、p024 双管道不同负责人均可区分单元。
21. 专业内名单为本项目该负责人全量历史派工工程师且排除离职；演示中「周离」不出现；未派工或全离职时名单空且不能提交。
22. 评估先是项目经理本人的项目列表，点进去才评该项目内的人；同一专业内工程师按姓名拼音升序，刷新后顺序不变。专业内未完成的专业必须有状态说明（尚未生成 / 草稿 / 待室主任审 / 已驳回），不能只给整页「暂不能评估」。
