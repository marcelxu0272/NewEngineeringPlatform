## 根因（双滚动条 / 裁切 / 模块重叠）

1. **旧一页 flex 高度链未拆净**：`.panel` 为 column flex；`.chart` / `.cash-chart-wrap` / `.target-chart` / `.delivery-layout` 等仍是 `flex:1; min-height:0`。
2. **双列改造用了 `display:contents` + `main` 的 `grid-auto-rows:minmax(...,auto)`**：行高改由内容决定后，与上条组合形成循环依赖——父行高靠子图，子图高靠父 flex → **图容器高度塌成 0**。
3. 探针曾见 cash/risk/contrib/delivery/alert 盒子 **y 区间相交**：图高为 0 时 Highcharts 仍按错误盒模型绘制/溢出，下一卡视觉上压住上一卡标题或曲线。
4. **滚动归属**：期望仅 `main` 纵向滚动；壳（Next `overflow-hidden` + iframe 外 pane）与 `html/body/.app` 应不滚。右侧条形/「99.2%」被挡，来自 **main 滚动条占用内容宽** + 图区高度不足，并非业务数据逻辑。

const ids = ['kpiGrid','cashPanel','riskPanel','contributionPanel','targetPanel','deliveryPanel','alertPanel'];

  const el = document.getElementById(id);

## 高度链二次返工（Max 重验失败后 · 同日续）

- 探针复跑：`docs/evidence/2026-11-02-ops-tree-visual-rework/run-probe.cjs` → **overallPass=true**，failures=[]

### 为何上次 min-height 未进文档流

1. 仍用 `display:contents` 把 middle/bottom 展平进 **CSS Grid** `main`。
2. `.panel` 作为 grid 子项又是 **column flex**，并带 `min-height:0` + `align-self:stretch`。
3. 在「grid 行高 auto ↔ flex 子项 intrinsic」循环里，行高只吃到标题/指标等非 flex 内容（盒高 ~91px）；`#cashChart` 虽设 height/min-height:220，却以 **overflow:visible 溢出绘制**，不撑开 panel 盒模型 → 与下方模块 y 相交；`main.scrollHeight===clientHeight`。

### 本次怎么改

1. **废除 contents 布局依赖**：DOM 扁平为 `kpi → cash → risk → pair-row(contrib|target) → delivery → alert → footer`。
2. **`main` 改为 `display:flex; flex-direction:column; overflow-y:auto`**（唯一纵滚）；`.app` 为 header+main 两行 grid，main `minmax(0,1fr)`。
3. **`.panel`：`flex:0 0 auto; min-height:min-content; height:auto; overflow:hidden`**，禁止叠画到下一卡。
4. 图表容器继续明确高度（现金流 220 / 目标 200 / 账龄 180 / 负荷 160），且 `flex-grow:0`。
5. t75u 保持：默认 blue；树 `ul/li` + 选中态背景写在 **li**（探针可测）随主题变。
