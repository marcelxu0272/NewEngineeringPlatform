## Problem Statement

经营管理者在「运营看板202610」的 Board 内容区查看经营全景时，需要一眼读清关键金额与负荷、用统一「较上期」对比口径、用红绿语义判断好坏变化，并在固定双列与看板目录下稳定切换；此前多轮改版与微调散落在变更账本中，缺少一份以**当前目标态**为准的公共规格，后续实现与验收容易漏项或回退到过时展示（例如曾短暂去掉现金流顶部指标卡）。

## Solution

以「运营看板 Board 可观测目标态契约」为**唯一测试缝合点**，把 Board 内容区（看板目录 + 右侧「运营看板」经营全景）的布局、指标卡字号、较上期文案、语义配色、账龄分布条、现金流三卡+当年趋势图与主题跟随，收成一份可验收的公共规格。规格描述**目标态**（含恢复现金流顶部三指标卡及其主金额配色），不以历史「去指标卡」为终点。组织图一级入口与原组织图路由行为保持不变，本规格不改造它们。

35. As a 经营管理者, I want 占位看板节点仍遵循统一双列骨架且不出现内容顶栏三下拉, so that 占位与真内容边界清楚。

## Implementation Decisions

- **唯一缝合点**：运营看板 Board 可观测目标态契约。一切验收落在 Board 内容区用户可感知的布局、文案、字号、颜色与图表形态；不新增数据接口或持久化契约作为本规格缝合点。
- **范围模块**：运营看板壳内的 Board 内容区——看板目录、树顶「运营看板」经营全景（KPI 二乘二、应收与资金风险、账龄与合同额结构、工作负荷与交付保障、经营贡献分析与板块目标达成、现金流与资金安全）、全局 header 主题对目录与主题色的跟随。
- **布局**：看板目录在左、内容在右；一级节点使用 Remix 风格图标；「运营看板」为树顶文案；经营全景内成对模块遵守统一双列栅格；工作负荷与交付保障为左四分之一、中二分之一、右四分之一且整体偏矮；板块目标达成与经营贡献分析同排等高。
- **指标卡字号**：顶部 KPI 四卡、应收四卡、负荷率两卡、现金流三卡的主金额或主百分比达到约三十像素量级（一眼可辨）；副文案可略放大；不得截断或挤破既有网格与已压低高度。
- **较上期**：用户可见副文案、标签与告警摘要中的对比口径统一为「较上期」；不以同比或环比作为对比标签。说明性 tip 中用于澄清「不是同比」的解释语可不作为阻断项。
- **语义色**：应收账款、WIP、存货——较上期降绿升红；营业收入——升绿降红；KPI「占目标」与「当月/上月新增」文案同色；KPI 金额与百分比跟随主题色。
- **账龄**：水平一条分布条，形态对齐合同额结构占比；图例一行四列对应四段账龄。
- **现金流区（目标态）**：顶部三卡为现金流入、现金流出、净现金流；其下为「当年现金流趋势」；柱为当月流入/流出上下叠排；折线为当年累计净现金流且正绿负红；图下留白充分；流入/流出主金额为主题色；净现金流主金额正绿负红，零值可用主题色或中性色且不得误用反色。
- **主题**：主题控件在全局 header；切换后看板目录与各主题色绑定元素跟随，不在各看板内容顶栏各自一套主题。
- **与历史账本关系**：本规格描述当前目标态。曾落地的「去掉现金流顶部指标卡」展示要求已被后续「恢复三卡」目标覆盖；趋势图相关已确认规则（当年趋势、叠柱、折线正负色等）继续有效。
- **正交边界**：不修改组织图原入口与源稿行为；不纳入目录注册/路由挂载公共规格或共用主数据与 SQLite 公共规格的职责。

## Testing Decisions

- 好的测试只断言 Board 可观测行为（可见文案、布局比例或同高、主值字号量级、计算色或可辨语义色、图表系列形态、主题切换后的跟随），不断言内部实现细节或开发自报探针。
- 优先在 Board 内容区对「运营看板」节点做端到端/页面级验收；可用独立自动化探针，但结论不得采信实现方自报。
- 回归抽检：组织图原路由行为未改；「较上期」无可见同比/环比对比标签回退；负荷三栏比例与压低高度、KPI 口径结构不因字号或现金流恢复而回退。
- 先验：变更账本与 `docs/evidence` 下运营看板相关独立验收记录所覆盖的行为，可作为本契约的既有通过样例；新实现须仍满足目标态（含三卡与配色）。

## Out of Scope

- 真实业务计算引擎、后端接口、权限与数据新鲜度。
- 组织图一级页实现细节以外的组织图产品改造；原组织图路由与源稿。
- 目录注册与路由挂载公共规格、共用主数据与统一 SQLite 公共规格。
- 占位看板节点的真实业务内容填充。
- 将 demo 假数替换为生产数据源。
- 本规格发布之外的业务实现入库策略（由产品/用户另行决定）。
